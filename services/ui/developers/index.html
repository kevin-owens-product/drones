Overview

Vehicles report through PX4, Betaflight or an adapter into a Go gateway, onto NATS and MQTT, into a FastAPI control plane backed by Postgres with PostGIS and Timescale. The console and every integration read the same API. Nothing on the command side is exposed: the platform monitors, records and sells.

Quickstart

Run the demo console and its API with no stack, in under a minute:

# the scripted sortie, every page marked DEMO DATA
git clone https://github.com/kevin-owens-product/drones
cd drones/services/ui && npm ci && npm run build && npm run demo
# http://localhost:4173 · the product site is at /product/
curl -s localhost:4173/v1/telemetry/live | jq '.items[0]'

Or run the full stack (control plane, gateway, NATS, Postgres, Keycloak, OPA, MediaMTX):

cp .env.example .env
make demo          # http://localhost:18080, sign in as gwen.analyst
make test          # unit suite; make ci adds lint and OPA
make sitl          # PX4 v1.18 SIH closed-loop trials

Auth, tenants and roles

The control plane signs users in with OIDC (Keycloak in development, PIV/CAC-backed in production) and keeps a session cookie. Every request is evaluated twice: an OPA policy decides the action from the role matrix, and Postgres row-level security scopes the rows to the caller's tenant. Allows and denies both land in the audit chain.

RoleCan
operatorRead the fleet, file field reports, propose a brief
planner, mission_commanderApprove briefs (not their own), request supply, build quotes
maintainerClose work orders, return airframes to service, receive shipments
ops_leadThe manufacturer's queue: ship, build, hold lots, plan surges
adminTenants, users, sharing agreements

Every response carries an X-Classification-Banner header with the highest marking on the page. Clients must show it.

Who can read and do what, as a test

The demo probes every read route and the writes that carry a rule as each of its accounts, and publishes the result as a table: docs/security/demo-access-matrix.md. A test fails when the table and the code drift, and when any of these stop holding: Neros's own routes answer 403 in a customer session, the audit log needs audit.read, accounts are listed per tenant, an allied tenant never receives a withheld field, an operator cannot approve a plan or hold a lot, and no caller can send a command inbound. Unknown routes answer 404.

            Stable · v1
            
Telemetry ingest (dmc/v1)

            
The stable way to bring a vehicle or sensor that is not PX4. It is telemetry only: an adapter reports state, never receives tasking. Send one JSON object per sample, by either route:

            
# MQTT
mosquitto_pub -t dmc/v1/<tenant>/<tail>/telemetry -m @sample.json
# HTTP, on the gateway
curl -X POST "$GATEWAY/ingest?topic=dmc/v1/<tenant>/<tail>/telemetry" -d @sample.json

            
A live sample from the demo fleet, in exactly the wire shape:

            

            

              
KeyTypeRequiredNotes

              
                
tail_numberstringyesMust match the topic's tail

                
tenant_idstringyesMust match the topic's tenant

                
timeRFC 3339yes

                
lat, londegreesyesOut-of-range rejects the sample

                
alt_mmetres MSLyes

                
classification, caveatsstring, string[]yesAbove system high rejects the sample

                
heading_deg[0, 360)

                
ground_mps, climb_mpsm/s

nav_source, gnss_trustedgnss | vio | none, boolDrives the console's denied-navigation display

              
            

            
Leave a key out when the source does not report it. Accepted samples are rate limited per tail.

Adapter conformance

            
services/gateway/internal/conformance holds a reference adapter for a small ground rover with its own autopilot and no MAVLink. Its test runs adapter output through the gateway's own decode, topic split and ingest pipeline and checks:

            
    
              
  • values map correctly (course −90 becomes 270, 7.2 km/h becomes 2 m/s, 15.4 V on 4S becomes 50%);
    • 
              
  • the wire keys are exactly the documented list;
    • 
              
  • mismatched tail or tenant, an out-of-range latitude, and a classification above system high are each rejected;
    • 
              
  • an overcharged pack is clamped, not rejected.
    • 
            

            
cd services/gateway && go test ./internal/conformance/

            
A new adapter copies that test with its own mapping. Limits: the test calls the pipeline in process, and nothing here has run against a real non-PX4 vehicle yet.

          


          

            Live · SIM
            
TAK and entity feeds

            
A customer's own fleet goes out as Cursor-on-Target events for a TAK Server and as Lattice-style entities. Own fleet only, outbound only. The entity shape follows Anduril's public Entities API documentation and has not been tested against a Lattice instance.

            

            

          


          

            Integrate
            
Versioning policy

            
    
              
  • The topic prefix dmc/v1 and the key names are the contract. Renaming or removing a key, or changing its unit, needs dmc/v2, served beside v1.
    • 
              
  • Adding an optional key is allowed in v1, so old adapters keep working.
    • 
              
  • proto/autonomy.proto follows the same rule through its package name (a2e.autonomy.v1). Removed field numbers are reserved and never reused.
    • 
              
  • Behavior packages are signed OCI artifacts; an unsigned package does not load.
    •
